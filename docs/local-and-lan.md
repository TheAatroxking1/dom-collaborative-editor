# 本地与局域网运行指南

这份文档说明三件事：本机怎么跑、局域网里怎么给别人用、以及换地址后怎么把本地内容搬过去。

本文命令使用 Windows PowerShell；Mac 用户请使用 [macOS 运行指南](macos.md)。地址、数据备份与迁移规则在两种系统上相同。

**先记住两个端口，不要混用：**

| 模式 | 前端地址 | 用途 |
| --- | --- | --- |
| 开发版 | `http://127.0.0.1:5273` | 改代码、热更新。**不启用离线页面缓存** |
| 构建版 | `http://127.0.0.1:5274` | 完整功能，包含离线刷新。**验收用这个** |

表中是服务电脑仍可手动访问的本机地址。构建版启动后默认打开局域网 IP，多个候选地址需先在终端选择编号；
没有候选地址时明确提示并回退 `127.0.0.1`。开发前端和构建版默认都监听 `0.0.0.0`，接受局域网连接；
`0.0.0.0` 是监听地址，不是浏览器访问地址。构建版本机地址或可信 HTTPS 可验收离线刷新，普通 HTTP 局域网地址不支持整站离线刷新。

两个端口分开是有原因的：生产 Service Worker 一旦安装，就会接管它所在 origin 的所有页面。
如果两种模式用同一个地址，你改完代码刷新看到的可能还是被 SW 缓存的旧产物。

**切换模式前先停掉另一个后端。** 即使端口不同，也不要有两个 Python 进程同时写同一个
`COLLAB_DATA_DIR`——那不是并发写入的问题，而是两个进程各自持有一份房间状态。

## 一、本机运行

### 安装

```powershell
py -3.12 -m venv backend/.venv
```

```powershell
.\backend\.venv\Scripts\python.exe -m pip install --require-hashes -r backend/requirements.lock
```

```powershell
npm --prefix frontend ci
```

以下示例在 Windows 自带的 PowerShell 5.1 或 PowerShell 7 中执行，启动命令使用系统自带的 `powershell.exe`，需要 Git、Python 3.12 和 Node 24.x。安装来源与版本检查见 [README](../README.md#快速开始windows)，不要求安装 uv。
所有命令从仓库根目录运行；macOS 的启动命令和未实测范围在上述专用指南中说明。

### 开发模式

```powershell
powershell.exe -NoProfile -File scripts/dev.ps1
```

打开 <http://127.0.0.1:5273>。这个脚本用 `taskkill /T /F` 强制结束子进程，适合日常开发，
不适合验证「正常停机」。需要正常停机时开两个终端：

```powershell
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8787 --workers 1 --timeout-graceful-shutdown 10
```

```powershell
npm --prefix frontend run dev
```

开发前端默认监听所有 IPv4 网卡，局域网设备访问 `http://实际局域网IP:5273`。
后端的 8787 仍只监听 `127.0.0.1`，页面请求与 WebSocket 都由 Vite 代理，不必开放 8787。
若前端也只供本机使用，改为 `npm --prefix frontend run dev -- --host 127.0.0.1`。

在跑后端的那个终端按 **Ctrl+C**，uvicorn 会进入正常关闭流程，应用会尝试写回完整文档状态。
请留意终端错误日志，连接排空的 10 秒限制并不是整个进程的总停机时限。

### 构建版（验收用这个）

```powershell
npm --prefix frontend run build
```

```powershell
powershell.exe -NoProfile -File scripts/serve.ps1
```

服务就绪后自动打开局域网页面，多个候选地址需先在终端输入编号。一个 Python 进程同时提供页面、API 与 WebSocket；前台运行，
Ctrl+C 正常停止。脚本会在缺少构建产物时提示先执行 build，不会替你安装依赖。

默认监听 `0.0.0.0:5274`。只允许本机访问时，追加 `-HostAddress 127.0.0.1`。
更新源码后先停止服务，重新构建前端并重启服务；旧版本页面有缓存时，结束编辑后关闭全部页面再重新打开。

不希望自动打开浏览器或交互选择地址时，使用：

```powershell
powershell.exe -NoProfile -File scripts/serve.ps1 -NoBrowser
```

这会在终端列出候选 URL。指定打开地址可改用 `-BrowserHost 192.168.1.100`，替换为服务电脑的实际 IP；
它与 `-NoBrowser` 互斥，也不会改变监听地址。没有交互输入的终端应明确使用这两种方式之一。

### 数据放在哪里

| 文件 | 内容 |
| --- | --- |
| `backend/data/v2/documents.sqlite3` | 文档目录（documentId 与创建时间） |
| `backend/data/v2/updates.sqlite3` | 正文的 CRDT 更新 |
| 浏览器 IndexedDB，库名 `dom-collab-v2:<documentId>` | 当前浏览器、当前地址下的本地副本 |

要整体备份服务端数据，请在**正常停止**之后复制整个 `COLLAB_DATA_DIR`。运行中直接复制
SQLite 主文件可能拿到不一致的快照。

## 二、局域网给其他设备用

默认启动入口会选择局域网地址，并在服务就绪后打开浏览器。已知地址也可以手动访问终端显示的 URL；
自动打开浏览器与列出候选地址都不代表另一台设备已能连接，仍需检查网络和防火墙。

### 先说清楚两件事

1. **HTTP 局域网可用但功能受限。** 其他设备通过 `http://你的IP:5274` 能正常协作、能在
   已打开的页面里断线编辑、能导出备份、复制链接失败时会显示可手动复制的字段。但**整站
   断网后刷新打不开页面**——SW 只在安全上下文可用，普通 HTTP 局域网地址不是安全上下文。
2. **完整离线刷新需要可信 HTTPS。** 下面用 mkcert 生成一张被访问设备信任的证书。不要用
   浏览器的「忽略证书错误」或启动参数绕过——那不是验证通过，只是把问题藏起来。

### 分享文档与选择地址

保持服务运行，在文档中点击「复制协作链接」。从 `localhost` 或 `127.0.0.1` 打开的页面，
会通过 `/api/share-addresses` 获取服务电脑的私网 IPv4，生成包含同一文档标识的局域网链接。
有多个候选地址时，选择双方设备能访问的网卡地址；VPN 或虚拟网卡的地址不一定适合。
没有候选地址或请求失败时，按页面提示检查网络，也可以手动使用已知的服务地址。

如果当前页面已经使用局域网 IP 或域名，分享保留原有协议、主机和端口。
生成链接不会跳转当前页面或更换当前浏览器的存储来源，不必把本机页面改成另一个地址才能分享。
另一台设备只需要浏览器；不要发送含 `127.0.0.1`、`localhost` 或 `0.0.0.0` 的地址。

要手动核对 Windows 当前网卡地址：

```powershell
ipconfig
```

找到双方可互通网卡的 IPv4 地址。自动列出地址不保证该地址可达，防火墙与网络隔离仍需检查。
建议在路由器上为这台机器保留 DHCP 地址，或者用固定的主机名，免得地址一变所有人手上的链接都失效。

### 生成可信证书

mkcert 需要你自行安装（Windows 可用 `choco install mkcert` 或从官方仓库下载）。把下面的
地址换成你**实际**的 IPv4：

```powershell
mkcert -install
```

```powershell
New-Item -ItemType Directory -Force .local-certs | Out-Null
mkcert -cert-file .local-certs/lan.pem -key-file .local-certs/lan-key.pem localhost 127.0.0.1 192.168.1.100
```

`-install` 只在本机注册根 CA。**访问设备必须另行信任这个根 CA 的公钥证书**，用
`mkcert -CAROOT` 找到根目录，按 mkcert 官方说明把 `rootCA.pem` 装到那台设备上。

证书的 SAN 必须覆盖访问和分享时选用的 IP 或域名；按钮不会替你验证证书，换了 IP 就要重新生成。
**`rootCA-key.pem` 绝不能分享**，
`.local-certs/` 整个目录也不进版本控制（`.gitignore` 已排除）。

### 启动并访问

```powershell
powershell.exe -NoProfile -File scripts/serve.ps1 -HostAddress 0.0.0.0 -Port 5274 -CertFile .local-certs/lan.pem -KeyFile .local-certs/lan-key.pem
```

其他设备打开 `https://实际局域网IP:5274`。地址栏不应有证书警告，页面里
`window.isSecureContext` 为 `true`。

页面、API 与 WebSocket 同源，因此不需要给其他设备单独配后端地址——前端用的是相对路径。

### HTTP 局域网（不用证书）

```powershell
powershell.exe -NoProfile -File scripts/serve.ps1 -Port 5274
```

其他设备打开 `http://实际局域网IP:5274`。在线协作与复制降级可用，界面会说明当前地址
不能启用离线页面缓存。由 HTTP 切到 HTTPS 相当于换地址，未同步的内容要先导出（见第三节）。

默认监听已接受局域网连接，无需额外指定 `-HostAddress 0.0.0.0`。
如果启动时显式指定了 `-HostAddress 127.0.0.1`，生成局域网链接也不会使服务对外开放；
需要停止服务并按上面的命令重新启动。

### 连不上时按顺序排查

1. 两台设备是否在同一网络、是否在同一网段；
2. Windows 防火墙是否允许该端口的入站连接（专用网络配置）；
3. 路由器是否开启了 AP 客户端隔离（访客网络常见）；
4. 是否挂着 VPN 或代理，导致流量没走局域网；
5. 端口是否被占用（换 `-Port` 再试）；
6. HTTPS 场景重点看证书：SAN 是否覆盖当前访问的地址、访问设备是否信任了同一个根 CA。

这些都需要你自己按需调整；脚本不会自动安装证书、修改防火墙或开放公网端口。

## 三、换地址后迁移未同步的内容

浏览器按 origin 隔离存储：`http://192.168.1.100:5274` 与 `https://192.168.1.100:5274`
是两份互不相干的本地数据。应用无法取消这条规则，所以未同步的内容需要显式搬过去。

升级后启动入口默认打开局域网 IP。如果原来用 `127.0.0.1` 或 `localhost` 编辑，先在旧地址打开原文档，
让未同步修改完成同步，或按下面步骤导出备份，再改用新地址；新地址不会自动继承旧地址的离线缓存。

### 五步迁移

1. **在旧地址打开原文档**，确认正文是你想搬的那一份。
2. **导出备份**：页面底部「备份与迁移」→「导出当前正文」，得到
   `<documentId>-<时间>.collab-backup.json`。文件里是完整的 Yjs 状态，包含你在离线时
   做的插入**和删除**。
3. **在新地址选择这个文件**：同一面板 →「选择备份文件」。你会看到文档标识、来源地址、
   导出时间和只读预览。
4. **打开原文档**：如果文件属于另一个文档，面板只提供「打开原文档」，不会写进当前正文。
   点它跳到对应文档。
5. **合并**：两份标识一致且正文已就绪时，「合并备份」才可点。合并前会先向当前服务器
   确认这份文档存在（8 秒超时），确认后把备份并入当前正文。

### 边界

- **合并是 CRDT 合并，不是回滚。** 早期备份不会撤销后来的删除，也不保证把内容恢复到
  导出那一刻的样子。重复导入同一份备份不会重复插入。
- **预览可以离线用；合并需要服务器在线。** 离线时可以导出与预览，点合并会明确提示
  需要连接服务端。
- **服务端没有这份文档时**（换了空数据库、搬到另一台服务器），合并会提示并保留预览，
  你可以把预览里的正文复制到自己新建的文档里。应用**不会**自动创建文档。
- **同一浏览器不同 origin、不同浏览器、不同设备之间都不共享本地缓存。** 每换一处都要
  走一次上面的流程。
- 服务端数据整体迁移请直接搬运 `COLLAB_DATA_DIR`（正常停止之后）。

## 四、离线页面缓存的实际范围

「页面资源已缓存」只说明**网页本体**能在断网时打开。正文能否离线看到，取决于**当前
浏览器在当前地址下是否打开过该文档**并写入过本地缓存。这两件事是不同的：

- 首次访问必须联网；
- 没打开过的文档，断网后打不开——界面会说无法获取正文，而不是给你一个空文档；
- 浏览器清除站点数据、隐私模式关闭、系统回收存储，都会移除本地副本，SW 对此无能为力；
- 有新版本时只提示，不自动刷新。结束编辑后关闭全部页面再重新打开即可更新。

细节见 [离线与局域网验收记录](offline-lan-validation.md)。
