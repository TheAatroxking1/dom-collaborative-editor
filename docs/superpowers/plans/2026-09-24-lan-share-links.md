# 局域网协作链接修复计划

**问题：** 从回环地址打开页面时，复制按钮沿用 `location.origin`，其他设备无法访问；构建版和开发前端原先也只监听回环网卡。

**方案：** 构建入口与 Vite 默认监听 `0.0.0.0`，保留显式指定回环地址的方式。后端增加无缓存的 `/api/share-addresses`，使用标准库提供主机局域网 IPv4 候选。前端只在本机地址页面上检测：一个候选自动采用，多个候选由用户选择，没有候选或接口失败时明确提示并可重试。已通过局域网 IP 或域名访问的页面保留原地址。

**边界：** 不修改当前页面地址或迁移浏览器存储；保留原协议、端口、路径和文档标识。检测结果只说明本机拥有候选地址，不能保证跨设备网络、防火墙或 HTTPS 证书可用。用户使用显式回环监听时仍只能本机访问。不新增依赖或修改同步、保存逻辑。

## 实施步骤

1. 后端测试先复现接口缺失，验证 RFC1918 过滤、去重排序、探测失败不影响文档服务，以及请求 Host 头不能注入候选。
2. 前端链接测试覆盖回环替换、原地址保留、IPv6 回环、无效候选；浏览器测试先复现按钮仍复制 `127.0.0.1`。
3. 实现地址 API 和前端选择、复制、失败重试。提前获取候选地址，点击时直接使用 Clipboard API，避免获取地址的网络等待耗掉浏览器用户手势。
4. 调整 Windows/macOS/Vite 默认监听和运行指南；不自动修改防火墙。
5. 验证后端、前端测试及构建；生产复制用例覆盖多地址、无地址、接口失败和手动复制；实际启动后用网卡地址打开第二浏览器上下文并验证同步。
6. 检查改动后提交、推送，并告知用户需更新源码、重新构建及重启服务。
